# Where is this number coming from?

The recurring question on this app: an invoice shows a number nobody typed, and
the answer could be any of five different code paths. Do not guess from the shape
of the string — run the tracer, it reads the actual rules and history.

## 1. Run the tracer

`avinashgroup_app/scripts/trace_number.py`. Read-only: it peeks counters without
drawing and writes nothing, so it is safe on a live site.

```bash
cd /home/sijan/frappe-15/sites
/home/sijan/frappe-15/env/bin/python -c "
import frappe
frappe.init(site='avinas1', sites_path='/home/sijan/frappe-15/sites'); frappe.connect()
from avinashgroup_app.scripts.trace_number import trace, trace_url
trace('Sales Invoice', 'NGK-SRTN-78/79-00417')
"
```

`trace_url('https://…/app/sales-invoice/NGK-SRTN-78%2F79-00417')` takes the URL
form directly — that is usually how the question arrives. `trace(dt, name,
field='custom_name')` traces a field other than the doctype's default target.

Run from `sites/`, not the bench root (Frappe builds the log path relative to cwd
— see CLAUDE.md), and never through `bench execute`, which blocks the engine's
`_`-prefixed helpers.

## 2. Read the verdict

| Verdict | Means | Where it came from |
| --- | --- | --- |
| `GENERATED` | the value decomposes into a rule's segments | the engine drew it; series key + counter are printed |
| `SUPPLIED` | not the rule's shape, not a copy of a source field | the write carried it (import row / REST / script) and it was stored verbatim — the correct state for legacy imports |
| `COPIED` | equals the rule's `legacy_source_field` | the rule's legacy window copied it from that field |
| `MIRROR OF THE DOCUMENT NAME` | value == `doc.name` | no rule produced anything; the fallback mirrored the naming-series name |
| `NOT ENGINE-OWNED` | no matching rule targets the field | whoever wrote the field; see WRITTEN BY |

`GENERATED` on a document that should have kept an imported number is the
interesting case. The tracer then prints **DISCARDED INPUT**: the legacy fields
that still hold what the write carried, whether another document holds that value,
and whether that document is in the same company or another one.

**WRITTEN BY** names the exact `Data Import` and the spreadsheet **row number**
(from `Data Import Log.docname`), plus any `Version` row that later changed the
field. This is the strongest evidence available — prefer it over inference.

## 3. Sweep for the whole population

Never conclude "one bad invoice" before checking how many there are:

```python
from avinashgroup_app.scripts.trace_number import find_regenerated
find_regenerated()                        # Sales Invoice / custom_branch_name
find_regenerated("Journal Entry", "custom_name", "custom_fact_numbering")
```

It lists every document holding a generated-shape number while the source field
holds something else. This is the query that found the 417 damaged NGK returns.

## 4. On the live site (ng-group)

No SSH and **read-only** access (see the ng-group memory): the user supplies an
API token in chat. Two options, in order:

1. Ask the user to run the snippet above in `bench --site <site> console` on the
   server and paste the output — full fidelity, and the script is read-only.
2. Reconstruct over REST yourself (GET only). The four reads that matter:
   `Sales Invoice/<name>`, `Numbering Configuration?fields=[…]` (segments come
   with the single-document GET), `Data Import Log?filters=[["docname","=",…]]`,
   and the same value queried group-wide to find who else holds it.

Aggregates work over REST too: `fields=["count(distinct custom_branch_name) as c"]`
with `group_by`, though `order_by` on the alias is ignored — compare a
`get_count` against a `count(distinct …)` per company instead.

## 5. Known cause, already fixed

If the verdict is `GENERATED`, the document is inside the rule's legacy window,
and the discarded value is held by **another company's** document — that is the
pre-2026-08-04 bug: `set_custom_branch_name` cleared an incoming number whenever
*any* document group-wide held it, then generated a replacement, silently. Numbers
are now unique per company and a duplicate throws. Repair for rows damaged before
the fix: `avinashgroup_app/scripts/restore_imported_voucher_numbers.py`
(`report()` then `restore()`).

Background: `docs/document_numbering_developer.md` §3 (uniqueness scope) and §4
(import extras). Engine: `custom_code/Override/naming_series.py`,
`set_custom_branch_name`.
