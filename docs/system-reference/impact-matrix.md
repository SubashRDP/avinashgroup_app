# Impact matrix: "if I change X, what moves?"

This table lists every custom field and setting that the HR/payroll code reads. For each one it gives:

- **Value on avinas1**, read on 2026-10-12.
- **Written by**: who or what sets it.
- **Read by**: the code that reads it, linked to the line.
- **If you change it**: what moves downstream.

The rows are grouped in pipeline order. Stage pages explain the mechanism in full:

- [01](01-masters.md) and [01b](01b-pay-masters.md): masters
- [02](02-checkin-to-attendance.md): attendance
- [03](03-shift-measurement.md): measurement
- [04](04-overtime.md): overtime
- [05](05-payroll-entry.md): payroll inputs
- [06](06-salary-slip.md): slip
- [07](07-after-the-slip.md): journal
- [08](08-changes-over-time.md): revisions
- [09](09-cross-cutting.md): cross-cutting

[hooks-inventory.md](hooks-inventory.md) says *when* each reader runs.

Some readers are **report-only** and never touch pay; those rows say so.

> **A general rule.** Almost everything here is read at the moment a document is *saved* or a button is *pressed*. Changing a setting does **not** rewrite existing Attendance rows, Additional Salary rows or salary slips. To make a change reach a month's pay, re-save or repair the attendance, press **Prepare Payroll Inputs** again, and re-save the draft slips. Prepare Payroll Inputs re-saves the slips itself. Submitted slips need cancel and amend.
